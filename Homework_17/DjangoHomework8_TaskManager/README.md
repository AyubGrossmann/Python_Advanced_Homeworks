# Домашнее задание 17 — безопасная пагинация и логирование

Проект продолжает Task Manager из ДЗ №8–16. Существующие модели, API,
Generic Views и мягкое удаление категорий сохранены.

## Задание 1. Безопасная пагинация

Выбран класс `CursorPagination`.

Почему:
- обычная пагинация по номеру страницы часто использует `page` и `offset`;
- CursorPagination использует специальный параметр `cursor`, а не открытый номер страницы;
- при большом количестве записей такой подход обычно лучше подходит для последовательного просмотра данных;
- размер страницы нельзя передать через URL и увеличить со стороны клиента.

Настройки находятся в `tasks/pagination.py`:

```python
from rest_framework.pagination import CursorPagination


class SafeCursorPagination(CursorPagination):
    page_size = 6
    ordering = ("-created_at", "-pk")
```

Пагинация подключена глобально в `settings.py`:

```python
REST_FRAMEWORK = {
    "DEFAULT_PAGINATION_CLASS": "tasks.pagination.SafeCursorPagination",
    "PAGE_SIZE": 6,
}
```

Поэтому она применяется ко всем спискам API: задачам, подзадачам и категориям.
На одной странице будет не больше 6 объектов.

Пример:
- откройте `/api/tasks/`;
- в ответе найдите поле `next`;
- перейдите по ссылке из `next`, чтобы получить следующую порцию данных.

Для CursorPagination используется параметр `cursor`, его значение формирует DRF.
Не нужно вручную придумывать или менять его.

## Задание 2. Логирование

В корне проекта создаётся папка `logs` с двумя файлами:

- `logs/http_logs.log` — HTTP-запросы и статусы ответов;
- `logs/db_logs.log` — SQL-запросы к базе данных.

### Логи сервера

Логи запуска Django-сервера выводятся в консоль PyCharm благодаря logger
`django.server` и обработчику `console`.

### HTTP-логи

Middleware находится в `tasks/middleware.py`.
Он записывает:
- HTTP-метод;
- путь запроса;
- статус ответа;
- время обработки запроса.

Пример строки:

```text
2026-11-09 11:00:00 INFO: GET /api/tasks/ -> 200 (0.025 сек.)
```

### Логи базы данных

В `settings.py` настроен logger `django.db.backends`.
Он записывает SQL-запросы Django в `logs/db_logs.log`.

SQL-логирование работает при `DEBUG = True`, как в учебной настройке этого проекта.
В production-среде подробное логирование SQL обычно отключают, так как оно может
создавать большие файлы и содержать чувствительные параметры запросов.

## Как запустить

Откройте папку `DjangoHomework8_TaskManager` в PyCharm.

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Новые миграции не нужны: модели не менялись.

## Как проверить

1. Запустите сервер командой `python manage.py runserver`.
2. Откройте `http://127.0.0.1:8000/api/tasks/`.
3. Проверьте, что в ответе есть `results` и ссылка `next` (если записей больше 6).
4. Перейдите по ссылке `next`.
5. Выполните ещё несколько запросов к API.
6. Откройте `logs/http_logs.log` — там должны появиться методы, пути и HTTP-статусы.
7. Откройте `logs/db_logs.log` — там должны появиться SQL-запросы.
8. Посмотрите консоль PyCharm — там остаются сообщения о работе сервера.

Для проверки логов можно выполнить в терминале:

```bash
# Windows PowerShell
Get-Content .\logs\http_logs.log
Get-Content .\logs\db_logs.log
```

## Структура добавленных файлов

- `tasks/pagination.py` — безопасная пагинация CursorPagination;
- `tasks/middleware.py` — запись HTTP-запросов и статусов;
- `settings.py` — глобальная пагинация и настройки логирования;
- `logs/` — папка для двух лог-файлов.


Обрати внимание: `http_logs.log` и `db_logs.log` создаются автоматически после
запуска сервера и выполнения запросов. В архиве они могут быть пустыми —
это нормально, сначала нужно запустить проект.
